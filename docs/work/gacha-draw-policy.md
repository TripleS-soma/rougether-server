# 뽑기 추첨 정책 리팩토링

2026-10-18 | 기준 main `58e9abf9eb2b60e9c6e27595380cf255479559e1`

뽑기 서비스에서 후보 선택 규칙과 난수 생성을 `GachaDrawPolicy`로 옮겼다. 추첨 규칙을 바꿀 때 지갑, 인벤토리, 원장 처리까지 읽거나 모킹해야 했던 문제를 줄이는 작업이다.

## 변경 전후

| 비교 항목 | 변경 전 | 변경 후 |
| --- | --- | --- |
| 추첨 책임 | `GachaService`가 등급 분류, 확률, 난수, 거래 처리를 함께 담당 | `GachaDrawPolicy`가 후보 선택, 서비스가 검증과 거래 실행을 담당 |
| 등급별 후보 준비 | 서비스에서 요청당 한 번 그룹화 | `prepare()`에서 요청당 한 번 준비한 `DrawPool`을 반복 사용 |
| 난수 제어 | 서비스 내부에서 `new Random()`을 생성 | 기본 난수는 유지하고 테스트에서는 생성자로 명시적 난수 주입 |
| 정책 테스트 | 서비스 private 필드와 메서드에 reflection으로 접근 | 저장소 모킹 없이 정책의 공개 API로 확률 경계와 후보 선택 확인 |
| DB 통합 테스트 설정 | 서비스 private 난수를 교체하고 종료 시 복원 | 테스트 전용 정책 빈에 난수를 주입하고 실제 정책 로직 실행 |
| 생성자로 주입하는 협력 객체 수 | 서비스 8개 | 서비스 9개. 새 정책의 저장소 의존성은 0개 |

응집도 개선 근거는 후보 선택과 거래 실행의 변경 이유를 분리한 것이다. 의존성 개수 자체는 줄지 않았으며, 정책 테스트가 서비스 내부 구조와 저장소 설정에 결합되는 부분을 제거했다. 조회 수나 처리 속도는 측정하지 않았으므로 성능 개선 효과를 주장하지 않는다.

## 보존하는 동작

- 확률: 난수 `0–69` 일반, `70–94` 희귀, `95–99` 전설. 해당 등급 안에서 균등 선택한다.
- 등급: 모두 `null`이면 등급 추첨 없이 전체에서 한 번 선택한다. 혼합 풀의 `null`은 일반으로 분류하고, 선택 등급이 없으면 전체 후보로 돌아간다. `weight`는 기존처럼 사용하지 않는다.
- 요청: `1`은 비용 1배와 결과 1개, `6`과 기존 앱의 `10`은 비용 5배와 결과 6개다.
- 지급: 보유하지 않은 보상만 지급한다. 같은 요청에서 먼저 받은 보상도 다음 추첨에서는 중복이며, 아이템은 다이아 3, 캐릭터는 코인 100으로 전환한다.
- 거래: 기존 `draw()` 트랜잭션, `user → COIN wallet → DIAMOND wallet` 잠금 순서, 해금 검사와 오류 판정 순서, 비용 차감과 지급, 환급, 원장 기록 순서를 유지한다.

카테고리와 보상 유효성 필터, 레벨 해금, 비용 계산, 보유 여부 판정, 빈 풀 오류는 서비스에 남긴다. API, DTO, DB 스키마는 바꾸지 않는다. 추첨 결과를 미리 일괄 생성하지 않고 기존처럼 한 번 선택할 때마다 지급 또는 환급을 처리한다.

## 검증

변경 전 검증은 기준 코드의 사용자 API 뽑기 테스트 6개 클래스에서 수행했다. 변경 후에는 같은 범위와 정책 테스트를 포함한 7개 클래스를 실행했다.

| 검증 범위 | 변경 전 | 변경 후 |
| --- | --- | --- |
| 사용자 API 뽑기 관련 테스트 | 95개 통과, 실패와 생략 0개 | 108개 통과, 실패와 생략 0개 |
| 전체 모듈 컴파일 | 이번 변경 전에는 별도 측정하지 않음 | 통과 |
| 전체 모듈 테스트 | 이번 변경 전에는 별도 측정하지 않음 | 2,693개 중 2,683개 통과, 10개 조건부 생략, 실패와 오류 0개 |
| `git diff --check` | 통과 | 통과 |

확률 경계는 표본을 많이 뽑아 비율을 추정하는 대신 정해진 난수로 경계를 직접 확인한다. 기존 통합 테스트의 실제 DB 반영 후 강제 실패와 새 JDBC 조회를 유지해 지갑, 인벤토리, 원장이 함께 롤백되는지 검증한다. 테스트 건수는 검증 범위의 기록이며 코드 커버리지 수치가 아니다.

잠금과 오류 판정 순서의 유지는 변경 diff 리뷰로 확인했다.

| 테스트 | 확인하는 내용 |
| --- | --- |
| `GachaDrawPolicyTest` 12건 | 확률 경계 6건, 같은 등급의 후보 순서와 반복 선택, 전체 null의 난수 1회, 혼합 null의 일반 분류, 누락 등급 3종의 전체 풀 fallback |
| `GachaServiceTest` 추가 2건 | 캐릭터 `6/10` 요청에서 신규 지급 1회, 중복 5회의 코인 500 환급, 비용 2,500과 최종 잔액, 원장 기록 |
| `GachaCategoryTransactionTest` 기존 8건 | 실제 DB의 비용, 지급, 환급, 원장 커밋과 지급 실패 시 전체 롤백, 카테고리 필터와 기존 앱 호환 |

기존 등급 없는 풀의 private 메서드 테스트 1건은 정책 테스트로 옮겼다. 따라서 전체 뽑기 테스트 건수는 정책 12건과 서비스 2건을 더하고 기존 1건을 빼서 비교한다.

전체 컴파일과 테스트는 5분 17초가 걸렸다. 각 모듈의 `build/test-results/test/TEST-*.xml` 385개를 합산했으며, 사용자 API는 2,069개 중 2,062개 통과와 7개 생략이다. 뽑기 관련 108개는 모두 실행했다.

생략 10개는 아래 환경 조건을 요구하는 기존 테스트다.

| 범위 | 생략 건수 | 실행 조건 |
| --- | --- | --- |
| libvips 네이티브 처리 | 2 | `VIPS_NATIVE_PATH` |
| 실제 FastAPI 계약 | 1 | `AI_SERVICE_CONTRACT_URL` |
| 실제 모델의 AI 사용자 평가 | 2 | `AI_USER_LIVE_EVAL`, 평가별 `AI_USER_LIVE_REGRESSION` 설정 |
| 실제 가구 생성과 개발 Lambda | 5 | `FURNITURE_LIVE_SMOKE`, `FURNITURE_FLARE_CONCURRENT_LIVE`, `FURNITURE_LAMBDA_DEV_SMOKE` |

정합성 코드 리뷰와 테스트 충실도 검토에서 차단 결함은 발견되지 않았다. 결과는 `codex/gacha-draw-policy`의 로컬 작업과 테스트 기준이며, 커밋, 병합, 운영 배포는 수행하지 않았다. 앞선 방 응답 리팩토링은 별도 `codex/room-response-reader` 작업에 보존되어 있다.

Java 25와 Docker의 MySQL 8.4 Testcontainers를 사용한다. CI 분할 속성을 지정하지 않고 아래 명령을 실행한다.

```bash
./gradlew :user-api:test --tests '*Gacha*' --console=plain
./gradlew compileJava test --console=plain
git diff --check
```

## 계약 확인 범위

로컬 스펙 `9693089`의 확률, 요청 수량, 중복 환급 계약을 확인했다. 원격 스펙 최신 여부는 확인하지 못했다. 모두 `null`인 풀의 구현 설명 등 일부 문서는 현재 코드와 차이가 있어, 이번에는 기준 코드의 기존 동작과 난수 호출 순서를 보존했다. 빈 등급의 확률 재분배, 레벨 해금 조건 등 새로운 정책 결정은 포함하지 않는다.
