# 거래소 구매 대기 및 채팅 연결 수정

## 거래소 조회 계약

`GET /api/v1/market/assets/{assetId}`에 `buyPending`, `sellPending`을 추가했다. 요청자 본인의 해당 종목 OPEN 주문 또는 PENDING PLACE 접수가 있으면 true다. 취소 접수 중에는 원래 OPEN 주문이 남아 있으므로 대기를 유지한다. 조회 트랜잭션에서 기존 repository 조건을 재사용하고 주문 처리나 재화 변경 규칙은 바꾸지 않는다.

`owned`는 실제 활성 인벤토리 보유만 뜻한다. 대기를 보유로 치환하지 않는다. 상세를 사용하는 앱은 대기 상태일 때 구매를 막고 내 주문으로 안내한다. 판매 주문이 없으면 구매 접수는 가능하며 자동 체결을 기다린다. 발행 응답에도 두 필드를 false로 제공한다.

## WebSocket 출처

React Native가 사용하는 API 출처 `https://dkfiwkal2ezg9.cloudfront.net`을 채팅 WebSocket에 명시적으로 허용한다. 기존 브라우저 출처에 `chat.websocket.allowed-origins`를 합치며, 배포 환경의 `CHAT_WEBSOCKET_ALLOWED_ORIGINS`로 네이티브 출처를 덮어쓸 수 있다. 여러 출처는 쉼표로 구분하고 빈 값으로 추가 출처를 제거할 수 있다.

일반 REST CORS는 그대로이며 전체 출처를 허용하지 않는다. 보안 CORS 필터의 정확한 `/api/v1/chat/ws` 경로와 WebSocket 핸들러가 `ChatWebSocketOrigins` 빈의 동일 목록을 사용한다. 핸들러만 수정하면 선행 보안 필터에서 403이 남는 것을 실제 소켓 테스트로 확인해 함께 수정했다. 기존 JWT 구독 인증 및 집 멤버십 검증도 유지한다. 통합 테스트의 실제 소켓 연결은 앱과 같은 Origin을 보내고 메시지, 읽음 및 강퇴 후 연결 종료까지 검사한다. 기존 웹앱 연결 허용과 미허용 출처 거절도 검증한다.

## iOS 푸시

모바일 PR #1583이 2026-10-28 개발 브랜치에 병합돼 있다. `content.data`가 비어 있으면 `trigger.payload`를 읽는 수정이며 탭, 수신, 표시 필터에 공통 적용됐다. 이번 작업에서는 동일 수정이나 서버 APNs 형식 변경을 중복하지 않고 기존 회귀 테스트를 재실행한다. 개발 브랜치 병합은 운영 OTA 수신 확인을 뜻하지 않는다.

## 적용 순서와 범위

공유 계약 문서를 동기화하고 서버를 먼저 배포한 뒤 모바일 거래소 화면을 반영한다. 이전 앱은 추가 필드를 무시하며 새 앱은 구 서버에서 누락된 필드를 false로 정규화한다. 따라서 대기 버튼 차단은 서버 필드가 배포된 이후 작동한다.

이 작업은 소스 수정 및 로컬 테스트다. 운영 주문, 재고, 재화, 컨테이너 설정은 수정하지 않았다. 운영 배포와 설치본의 실제 푸시 클릭 확인은 별도 단계다.
