# 활동 기록 API 개선 반영

인증 요청의 일별 활동 기록을 요청 스레드에서 모아 독립 트랜잭션으로 커밋한다. API 경로·응답·DB 스키마는 유지한다. 이 변경에는 클라우드 자원 생성, 인스턴스 사양·대수 변경, 배포 워크플로 변경이 없다.

## 실행 설정

| 설정 | 기본값 | 의미 |
| --- | --- | --- |
| `ACTIVITY_BATCH_ENABLED` | MySQL 프로필 `true`, 그 외 `false` | 활동 기록 묶음 커밋. `false`로 기존 개별 기록 경로로 복귀한다. |
| `ACTIVITY_BATCH_SIZE` | `100` | 한 묶음의 최대 참여 기록 수 |
| `ACTIVITY_BATCH_QUEUE_CAPACITY` | `512` | 인스턴스별 대기 기록 수 상한 |
| `ACTIVITY_BATCH_COLLECT_MILLIS` | `2` | 수집 대기 설정. DB 대기·스케줄링을 포함한 응답시간 상한은 아니다. |
| `ACTIVITY_SHARED_CACHE_ENABLED` | `false` | 기존 Redis 주소를 명시한 환경에서만 별도로 활성화한다. 묶음 커밋은 Redis 없이도 동작한다. |

공유캐시를 사용하는 환경은 `ACTIVITY_SHARED_CACHE_HOST`, `ACTIVITY_SHARED_CACHE_PORT`를 지정한다. TLS·인증이 필요하면 `ACTIVITY_SHARED_CACHE_SSL_ENABLED=true`, `ACTIVITY_SHARED_CACHE_PASSWORD`를 비밀 저장소에서 주입한다. 이 변경으로 Redis 서버가 생성되지는 않는다.

## 처리와 실패 경계

- KST 날짜의 로컬 완료 표식을 먼저 확인한다. 같은 인스턴스의 동일 사용자 처리 중 집합은 완료 집합과 분리한다.
- 첫 기록이 동시에 들어오면 최대 지정 크기까지 모으고 요청 스레드 하나가 `REQUIRES_NEW` 트랜잭션을 실행한다. 별도 worker는 없다.
- 참여 요청은 DB 커밋 결과까지 기다린다. 활성 사용자별 결과를 조회해 확인하고 커밋 성공 뒤에만 L1·Redis 완료 표식을 저장한다.
- 봇·탈퇴·없는 사용자는 제외하고 사용자·날짜 UNIQUE로 중복 저장을 막는다. 활동 기록과 API 업무 트랜잭션은 독립적이다.
- DB 실패·대기열 포화는 기존 활동 관측 실패 정책을 따른다. 기록 실패를 계수하고 완료 표식을 남기지 않으며 다음 요청에서 재시도한다. 업무 요청은 진행한다.
- 선택적 Redis 경로는 장애 시 DB로 우회한다. 250ms 뒤 인스턴스별 한 조회만 복구를 확인하고, 실패하면 대기를 최대 5초까지 늘린다. Redis I/O 중 호출자의 DB 트랜잭션을 점유하지 않도록 외부 트랜잭션에서는 우회한다.

## 검증과 반영 범위

활동 기록 실험 커밋 `6325c375`, `d979f243`, `7dd16e0b`의 API·영속 계층·테스트를 최신 main에 적용했다. 온보딩 요약 캐시, 해당 기능의 DB migration, 부하 발생기와 AWS 실험 도구는 포함하지 않는다.

실제 MySQL 통합 테스트는 `mysql` 프로필의 기본 활성화 설정으로 실행하며, 동시 기록·중복·제외 대상·호출자 롤백으로부터 독립된 커밋·커밋 직전 실패와 재시도를 확인한다. Redis 선택 경로는 연결 비활성·TLS·장애 복구와 커밋 이후 표식 저장을 별도로 검증한다.

기존 성능 수치는 격리 AWS 환경의 실험용 JAR에서 측정한 결과다. 이번 최신 main 조합이나 현재 서비스 용량을 재측정한 값으로 사용하지 않는다. 자동배포의 `hold` 상태와 클라우드 자원 구성은 이 변경에서 유지한다.
