# 집 미션 조회 분리 리팩토링

2026-10-18 | R3 | 기준 main `d96ffc8782534448e983d636d07e429a7bf40560`

집 미션의 목록, 상세, 미리보기 조회를 `HouseMissionQueryService`로 옮겼다. 조회 응답을 수정할 때 생성, 기여, 보상 처리까지 함께 읽어야 했던 구조를 정리한 작업이다. API 응답과 DB 스키마는 유지한다.

## 변경 전후

| 비교 항목 | 변경 전 | 변경 후 |
| --- | --- | --- |
| 조회 책임 | `HouseMissionService`에 조회와 쓰기가 함께 있음 | `HouseMissionQueryService`가 조회, 일괄 집계, 응답 조립을 담당 |
| 쓰기 책임 | 같은 서비스에서 생성, 삭제, 직접·자동 기여, 보상 수령을 처리 | 기존 서비스에 이 다섯 진입점과 트랜잭션을 유지 |
| 읽기 호출자 | 미션 컨트롤러, 집 미리보기, AI 사용자 상태 조회가 혼합 서비스에 의존 | 세 호출자가 조회 서비스를 사용 |
| DAILY 계산 | 혼합 서비스의 private 메서드 두 개 | `HouseMissionProgressCalculator`의 순수 함수 두 개를 조회와 쓰기에서 공유 |
| 읽기 트랜잭션 | 조회 메서드 세 개에 각각 `readOnly = true` | 조회 클래스에 `readOnly = true` |
| 서비스 크기 | 461줄, 공개 업무 메서드 8개 | 쓰기 319줄·5개, 조회 192줄·3개. 계산기는 21줄 |
| 주입 의존성 | 혼합 서비스 9개 | 기존 쓰기 서비스 9개 유지. 조회 서비스는 저장소 6개, 계산기는 주입 의존성 없음 |

줄 수는 주석과 빈 줄을 포함하며 생성자는 업무 메서드 수에서 제외했다. 총 코드량이나 의존성 개수가 줄었다는 의미는 아니다. 조회가 금칙어 검사, 알림 발송, 루틴 연결 해제에 의존하지 않도록 변경 이유를 분리한 것이 핵심이다. 단순한 집·회원 가드는 각 서비스 안에 두어 조회와 쓰기가 서로 호출하지 않게 했다.

공개 조회 메서드를 클래스 위쪽에 모으고 집계와 가드는 아래에 배치했다. 기존 쓰기 서비스의 이름과 생성자는 유지해 루틴, 봇, AI 실행 경로의 변경을 최소화했다. 조회 성능과 SQL 실행 시간은 별도로 측정하지 않았으므로 성능 개선을 주장하지 않는다.

## 보존한 동작

| 영역 | 그대로 유지하는 조건 |
| --- | --- |
| 목록과 상세 권한 | 집 존재·미삭제 → ACTIVE 구성원 → 해당 집의 미삭제 미션 순서로 검사 |
| 목록 | 최신 생성일과 ID 내림차순, 일괄 집계, 개인 누적 기여와 오늘 기여 여부 |
| 미리보기 | 바깥 집 조회에서 공개 여부를 검사. 개인 기여 필드를 생략하고 개인 기여 쿼리도 실행하지 않음 |
| DAILY | Asia/Seoul의 오늘 기준. 활성 기여자 비율은 내림 표시, 달성은 정수 비율로 판정. 멤버 0 이하면 진행률 0과 미달성 |
| 수령 표시 | `todayClaimed`는 DAILY에만 제공하고 WEEKLY는 null로 JSON에서 생략 |
| 기여와 알림 | 하루 한 번 기여, 기여와 알림 내역 저장의 원자성 |
| 자동 기여 | `MANDATORY`로 루틴 완료 트랜잭션에 참여. 미션·회원·오늘 기여의 잠금 조회 유지 |
| 보상 | 최초 집 접근부터 `house → mission` 순서로 잠금. DAILY 보상 이력과 +20, WEEKLY 완료 처리와 +100을 같은 트랜잭션에서 반영 |
| 삭제 | 미션 삭제와 연결 루틴 해제를 같은 트랜잭션에서 처리 |

기준 코드와 비교해 쓰기 서비스에 남긴 11개 메서드 본문 및 조회 서비스로 옮긴 11개 메서드 본문이 동일함을 확인했다. 계산식도 그대로 옮겼다. 생성, 기여, 보상의 처리 순서를 재구성하지 않았다.

## 계약 확인 범위

스펙 저장소의 최신 `origin/main`인 `adfddc3`을 확인했다. 개인 기여 필드, KST 기준, DAILY/WEEKLY 계산과 보상 규칙을 대조했다. 스펙 체크아웃은 과거 브랜치여서 원격 추적 main의 파일을 직접 읽었다.

기존 문서에는 미리보기를 전체공개로 설명하거나 상세를 목록 필드 전체에 `achieved`를 더한 형태로 설명하는 부분이 남아 있다. 이번에는 현재 동작대로 비공개 집의 비구성원 접근을 거부하고, 상세에 `contributedToday`를 새로 추가하지 않았다. API 정책을 바꾸는 작업과 구분한다.

## 최신 main 통합 검증 (2026-10-18)

리팩토링 커밋 `096b0088`에 최신 main `14d20b39`를 합친 `ee4ebe59`에서 병합 전 검증을 수행했다. main에 추가된 피드 대댓글 처리를 보존했으며, `AiUserObserver`의 차이는 미션 조회 서비스 import와 주입 타입 두 곳뿐이다. 마이그레이션 92개의 내용은 main과 같고 버전 중복은 없다.

`./gradlew compileJava test --console=plain`과 `git diff --check`가 통과했다. XML 389개 기준 전체 2,734개 중 2,724개 통과, 기존 환경 조건에 따른 10개 생략, 실패와 오류 0개다. 사용자 API는 2,109개 중 2,102개 통과와 7개 생략이다. 입력이 바뀌지 않은 태스크는 Gradle의 `UP-TO-DATE` 결과를 재사용했다.

기존 집중 범위에 해당하는 14개 클래스는 전체 실행에서도 131개 모두 통과했다. 독립 검증의 124개보다 7개 늘어난 것은 최신 main에서 AI 사용자 통합 테스트가 추가됐기 때문이다. 이번 리팩토링 자체의 테스트 순증은 앞서 기록한 12개다.

최신 main 대비 최종 diff에 대한 정합성 재리뷰도 PASS였으며 차단할 문제는 없었다. CI 결과와 병합 상태는 해당 PR에서 별도로 확인한다.
