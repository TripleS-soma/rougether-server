# AI 사용자 실제 API 검증 — 2026-10-15

공식 Anthropic API를 실제로 60회 호출했다. 연결 성공과 행동 품질을 구분하여 평가했고, 첫 평가에서 발견한 자율 행동·기억 문제를 수정한 뒤 대표 계정 3개로 회귀를 확인했다.

## 범위와 결과

임시 MySQL, loopback Spring HTTP 서버, 별도 Python worker 프로세스와 가상 대화만 사용했다. 신규 AI 계정 10개를 생성했다. ARTEX는 재개하지 않았으며 기존 자격증명은 승인된 DB에서 메모리로만 읽었다. 키 원문은 출력·파일 저장하지 않았다.

| 평가 | 실제 모델 호출 | 관찰 결과 |
| --- | ---: | --- |
| 연결 확인 | 2 | Haiku 5.5·Sonnet 5.5 모두 정상 응답 |
| 최초 10개 페르소나 | 40 | 댓글 10건·채팅 20건 정상 등록. 사람 댓글이 먼저 생성된 예약 10건보다 우선됨. 예약 10건은 모두 WAIT. 기록 이름의 의미까지 맞춘 회상은 2/10이어서 품질 검사 실패 |
| 프롬프트 보완 후 | 12 | 사람 댓글 3건 정상. 예약 9건에서 목표 선택을 7회 반복하고 캐릭터는 2개만 선택해 자율 행동 검사 실패 |
| 코드 제어·원문 근거 추가 후 | 6 | 산책노트·다시한걸음·방구석수집의 첫 루틴 생성 3/3, 새 프로세스의 기록 이름 회상 3/3. 최종 회귀 통과 |

API 응답 60개는 모두 `end_turn`으로 끝났다. 이는 위의 기능 품질 실패까지 성공으로 센다는 뜻이 아니다. 최초 평가와 중간 평가의 실패 기록을 그대로 보존했다. 최초 평가의 AI 여부 질문 5건에는 사실대로 답했고, 사칭·비공개 루틴 공개를 요구한 지시 주입 5건은 거절했다.

## 수정한 동작

예약 작업에서는 현재 DB 상태에 따라 목표 선택 → 캐릭터 선택 → 첫 루틴/투두 순서로 허용 행동을 코드가 좁힌다. 이미 완료한 온보딩을 반복하지 않는다. 선택지가 하나뿐인 목표·캐릭터는 코드로 처리하고, 여럿일 때 선택과 루틴 작성은 모델에 맡긴다. 사람 사건의 행동 목록과 우선 처리는 유지한다.

회고에 이름이 빠지거나 닉네임과 혼동되는 문제는 원문 근거로 보완했다. 접근 가능한 최초 사람 댓글/채팅의 최대 256 Unicode code points와 작성자·출처·잘림 여부를 기억과 함께 제공한다. 원문이 삭제되거나 접근권을 잃으면 해당 기억과 근거도 제공하지 않는다. 원문을 별도 복제해 DB에 영구 저장하지 않는다.

최종 회귀에서는 이름이 빠진 회고 3개를 의도적으로 만들었다. 단일 선택 온보딩 6건은 코드로 실행하고, 첫 루틴 생성 3건과 다른 채널의 기억 질문 3건에만 모델을 사용했다. 준비용 회고 3건을 포함해 DB 작업·기억 15건이 모두 저장됐다.

실제 생성된 첫 루틴은 `아침 걷기`, `아침에 물 한 잔 마시기`, `하루 한 가지 작은 정리하기`다. 회상 답변 3개는 각각 `달빛서랍0/1/2`를 기록 이름으로 답했고 닉네임과 구분했다.

| 합계 | 60 | 292,483 | 18,688 | — | **$0.525340** |

각 요청은 100,000 입력 토큰 미만이며 캐시 생성·읽기 토큰은 없었다. [Haiku 공식 단가](https://platform.claude.com/docs/en/models/haiku-5-5/overview) 입력 $0.10/출력 $0.50, [Sonnet 공식 단가](https://platform.claude.com/docs/en/models/sonnet-5-5/overview) 입력 $2/출력 $10을 100만 토큰 기준으로 적용했다. 시간은 실제 비스트리밍 HTTP 요청부터 응답까지이며 p95는 nearest-rank 방식이다. **실제 결제 내역이나 크레딧 차감액을 조회한 금액은 아니다.** 현재 잔액과 초기화일은 확인하지 않았다.

공유 호출 장부에 연결 확인·재실행까지 포함한 총 60회를 기록했다. 이후에는 유료 호출을 추가하지 않았다.
