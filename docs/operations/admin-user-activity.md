# 관리자 사용자 활동 조회

폐지된 악세사리 관리 메뉴 위치의 **사용자 활동**에서 조회한다. 유저 관리 화면과 분리되어 있다.
기존 `/accessory-render-profiles` 링크는 `/user-activities`로 이동한다. 기존 악세사리 데이터와 API는 변경하지 않는다.

## 조회 방법

- 기본 조회일은 한국 시간 오늘이다. 오늘부터 365일 전까지 날짜를 선택한다.
- 닉네임 또는 사용자 ID, 사용 기능, 행동 기록 유무로 사용자를 찾는다. 기능 필터는 해당 기능 기록이 있는 사용자를 고르며 그 사용자의 다른 기능도 함께 표시한다.
- 요약 카드는 현재 페이지가 아닌 조회 조건에 맞는 전체 사용자 기준이다.
- 각 사용자에서 기능별 시각과 집계 기준을 펼칠 수 있다. 봇, AI, 탈퇴 계정은 제외한다.
- `GET /admin/user-activities`는 관리자 세션의 ADMIN 또는 SUPER_ADMIN 역할이 필요하다.

## 해석 범위

이 화면은 기존 업무 DB에 남은 기록을 읽는다. **화면 열기, 읽기, 클릭을 수집한 분석 도구가 아니다.**
취소, 삭제, 덮어쓰기된 기록을 복구하거나 누적 사용 횟수를 추정하지 않는다. 본문과 이메일은 조회하지 않는다.

| 기능 | 날짜와 건수의 기준 |
| --- | --- |
| 인증 활동 | 일별 인증 여부와 마지막 로그인/토큰 갱신 시각. 일별 기록의 적재 시각은 실제 요청 시각이 아니므로 표시하지 않음. 행동 건수 제외 |
| 가입, 루틴/할 일 생성 | 생성 시각. 온보딩 생성도 포함 |
| 루틴/할 일 완료 | 현재 완료 상태의 실제 완료 시각. 예정일과 다를 수 있고 완료 취소 시 빠짐 |
| 방 꾸미기 | 현재 남아 있는 배치의 마지막 수정, 배경 슬롯의 마지막 저장 시각. 저장/이동 횟수가 아님 |
| AI 가구 요청 | 요청 생성 시각. 업로드 대기/실패 포함, 완성 수가 아님 |
| 뽑기, 상점 구매 | 결제 원장 생성 시각과 원장 건수. 무료 뽑기, 물품 수와 다름 |
| 가구 구매/판매 | 고정가 구매와 이전 거래소 체결 시각. 판매 등록/가격 변경은 미포함 |
| 피드/댓글/답글 | 작성 시각. 삭제 후에도 업무 기록이 남아 있으면 포함 |
| 집 참여/응원, 채팅, 방명록 | 마지막 참여, 응원 전송, 메시지/방명록 생성 시각 |
| 미니게임 | 실행 시작 시각. 미완료 게임 포함 |
| 출석 | 출석 생성 시각 |

좋아요와 알림 읽음은 저장된 시각이 없어 일별 조회에 포함하지 않는다.
‘접속 기록만 확인’은 다른 기능을 사용하지 않았다는 뜻이 아니며 실시간 온라인 상태도 아니다.

## 운영 비용

사용자 API 쓰기 경로에는 변경이 없다. 읽기 쿼리는 KST 하루의 UTC 반개구간으로 원본 테이블을 집계한다.
시간 선두 인덱스가 없는 테이블도 있어 누적 데이터가 늘면 조회 비용을 재확인해야 한다.

- 날짜별 결과는 빈 결과를 포함해 15초간 재사용하며 최대 8일을 보관한다. 실패는 캐시하지 않는다.
- 관리자 프로세스당 DB 집계는 한 번에 하나만 실행한다. 잠금을 200ms 내 얻지 못하면 503 `ADMIN_ACTIVITY_BUSY`를 반환한다.
- 캐시 대기/적중 시 DB 트랜잭션을 열지 않는다. 실제 조회에만 읽기 전용 트랜잭션 10초, JDBC 쿼리 제한 5초를 적용한다.
- 화면의 집계 시각은 캐시를 생성한 시각이다. 서버가 여러 개면 캐시는 프로세스별이다.
- 페이지 크기는 1~100, 기본 30이다. 하루 집계 후 사용자 필터와 페이지를 적용한다.

운영에서 느려지면 대표일 실행계획과 실제 행 수를 먼저 확인한다. 사용자 수만으로 쿼리 비용을 추정하지 않는다.
