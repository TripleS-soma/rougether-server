# 크리스마스 누적 3일차 여우

크리스마스 누적 3일차에는 기존 30코인과 여우 캐릭터 여루를 함께 준다. 고양이 캐릭터는 루양이로 표시한다. V103은 한국어 표시 이름만 변경하고 code, 번역 JSON과 보유 이력을 보존한다. 5일마다 총 60코인, 30회 누적, 종료일은 유지한다. 여우는 한 번만 지급하고 자동 착용하지 않는다. 보유한 활성 캐릭터 교체는 레벨 제한 없이 허용하며 캐릭터 뽑기 레벨 10 조건은 유지한다.

## 반영 순서

1. 서버 PR의 CI와 전체 테스트를 확인한 뒤 `.github/workflows/docker-publish.yml` 정식 blue-green 경로로 배포한다. 진행 중인 배포가 있으면 기다린다. V102는 여우를 비활성 상태로 등록하고 기존 이벤트와 연결한다. 이 단계는 사용자에게 여우를 지급하지 않는다.
2. 승인된 원본을 아래 새 CDN key로 업로드하고 크기, 투명도, 파일 해시와 실제 CDN 응답을 대조한다. 기존 파일을 덮어쓰지 않는다. `idle.webp`는 눈과 꼬리만 움직이는 승인본이다.
3. fox 코드를 지원하는 앱의 캐릭터 교체, 출석 카드, 수령 복구 경로와 실제 재생을 확인한다. 심사 중 production OTA 정책은 모바일 `docs/release-ops.md`를 따른다. 서버 배포만으로 신규 앱 반영을 주장하지 않는다.
4. 앱 공개 뒤 admin에서 여우를 활성화한다. 기본 이미지와 세 포즈가 준비되지 않으면 활성화하지 않는다. 기존 출석 이벤트와 코인 설정을 다시 생성하거나 재활성화할 필요는 없다. 과거 이벤트 오픈 도구의 정규 풀 기준은 빙하 테마 추가 전 값이므로 현재 운영 DB에 재실행하지 않는다.
5. 운영 검증은 마스터 조회와 정식 배포 진단으로만 한다. 실사용자 대신 출석하거나 캐릭터를 지급하는 테스트, 푸시 또는 전체 사용자 알림은 하지 않는다.

| 용도 | asset key |
| --- | --- |
| 기본 정지 이미지 | `characters/fox/base-v1.webp` |
| rest, 눈 깜빡임과 꼬리 | `characters/fox/animations/idle.webp` |
| seated 정지 포즈 | `characters/fox/animations/pose-cycle.webp` |
| tail-rest 정지 포즈 | `characters/fox/animations/wave.webp` |

마지막 두 key는 기존 admin 활성화 검사와의 호환을 위한 이름이다. `character_poses.code`는 각각 `seated`, `tail-rest`다. wave 파일을 손 흔드는 애니메이션으로 설명하지 않는다.

## 기존 출석자와 구버전 앱

누적 3회 이상 출석한 계정은 새 앱 접속 시 `POST /api/v1/events/attendance/{eventId}/character-reward`로 여우만 수령한다. 오늘 출석을 대신하지 않고 코인이나 출석 기록도 늘리지 않는다. 읽기 API는 지급하지 않는다. 자동 수령 요청은 훅 수명 동안 계정과 이벤트별 한 번만 시도하며, 실패하면 같은 이벤트를 GET으로 확인하고 수동 수령 버튼을 제공한다.

기존 앱은 알 수 없는 fox 코드를 보유 목록에서 제외하고 방 표시에서도 해석하지 못한다. 서버 활성화만으로 구버전의 여우 표시와 교체가 해결되지 않는다. 지급은 selected=false이므로 현재 대표 캐릭터는 바뀌지 않는다. 새 앱으로 업데이트하면 내 정보 → 프로필 편집 → 캐릭터 변경에서 선택할 수 있다. 선택은 전체 화면의 3열 목록이며 별도 내부 스크롤 영역을 두지 않는다. 구버전에서 활성화 후 3회 이상 출석하면 서버가 여우를 지급할 수 있으므로 이 호환 한계를 출시 안내에 반영한다.

유저 행 잠금과 삭제 이력까지 포함한 `user_characters` 존재 확인으로 중복을 막는다. 삭제된 보유 이력이 있으면 재지급하거나 코인으로 환산하지 않는다. 이력을 임의로 지우면 지급 방어가 깨진다.

## 롤백

여우 지급을 멈출 때는 admin에서 여우를 먼저 비활성화한다. 이후 필요한 서버 롤백은 같은 정식 blue-green 경로만 사용한다. 이전 서버는 `is_attendance_reward`를 알지 못하므로 활성 여우를 둔 채 이전 코드로 되돌리면 무료 초기 선택 후보에 들어갈 수 있다. 비활성화가 확인되기 전에는 이전 서버로 되돌리지 않는다. 마이그레이션 컬럼과 지급 이력을 삭제하지 않는다. 이미 선택한 여우가 있는 계정의 표시는 별도 확인한다.
