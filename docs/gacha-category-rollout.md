# 뽑기 세 카테고리 이행 검증

사용자에게 보이는 장식 뽑기는 벽지·바닥·가구 세 종류입니다. 기존 테마 머신의
실제 운영 풀을 V63에서 이관하며, 캐릭터와 악세사리의 기존 획득 API는 유지합니다.

## 배포 순서와 호환성

새 모바일은 응답의 `category`와 실제 `gachaId`로 머신을 선택합니다. 기존 모바일은
`themeId=null`을 캐릭터로 해석하므로 앱 업데이트와 서버 V63 적용을 조율해야 합니다.
기존 공개 목록을 클라이언트에서 임의로 합치거나 가짜 ID를 발급해서는 안 됩니다.

서버 운영 DB 조회·수정이나 배포는 이 변경의 검증에 포함되지 않았습니다. 배포 직전
최신 main의 Flyway 번호와 V63 충돌 여부를 다시 확인합니다.

## 데이터 편입 범위

V63은 현재 시작된 활성 상시 머신의 활성 ITEM 엔트리를 배치 유형으로 분류합니다.
벽지와 바닥은 `surface_slot`의 정확한 슬롯값을 확인하고, 러그를 포함한 `positioned`
아이템은 가구로 보냅니다. 배경·캐릭터 악세사리·상충하는 배치 정보는 제외합니다.

종료일이 있는 한정 머신, 아직 시작하지 않은 머신, 비활성 머신과 풀은 편입하지
않습니다. 같은 아이템의 중복은 한 행으로 합치며 등급 충돌은 전설·희귀·일반 중
최상위 지원 등급을 보존합니다. 기존 등록에 등급이 없으면 일반입니다. 아이템이나
테마 자체가 비활성이어도 기존 풀 등록은 유지하며, 사용자 조회와 추첨의 활성
필터가 실제 배출을 막습니다. 기존 머신·풀 행과 이력 ID는 삭제하지 않습니다.

상점에만 있고 뽑기 풀에 한 번도 등록되지 않은 기존 상품에는 이번 이행이 새 확률을
부여하지 않습니다. 따라서 특정 카테고리가 비어 있을 수 있습니다. 운영 전
진단으로 확인하고 편입할 아이템·등급을 결정한 뒤 관리자의 등급 지정 경로로
등록합니다. 신규 카탈로그 적재에서 활성 장식은 일반 등급으로 자동 등록되지만,
기존 상품 재적재는 원래 등급과 회수 상태를 보존합니다.

## 읽기 전용 진단

`deploy/sql/verify_gacha_categories.sql`은 모두 SELECT인 MySQL 8 진단 스크립트입니다.
승인된 운영 연결에서 이행 전후 각각 실행해 결과를 보관합니다.

- 세 정식 코드가 각각 한 개이고 25 COIN·1회·테마 없음·활성인지 확인합니다.
- `eligible_catalog_count`와 `included_pool_count`의 차이 및 누락 상세를 비교합니다.
  `gap_count`는 의도적으로 제외한 상품도 포함하므로 자동 편입의 근거로 사용하지 않습니다.
- 세 카테고리의 `included_pool_count`가 모두 1 이상이어야 뽑기 화면을 완전하게 운영할 수 있습니다.
  비어 있는 풀은 `EMPTY_POOL`을 반환하며 코인·보상 이력을 남기지 않습니다.
- 중복 활성 등록과 잘못된 보상 조회는 0행이어야 합니다.
- 등급별 보상 수를 확인합니다. 빈 등급은 기존 계약대로 전체 유효 풀 균등 추첨으로
  대체되므로 모든 풀에서 유효한 실효 확률이 70/25/5인 것은 아닙니다.

이행 후 테스트 계정으로 각 카테고리 미리보기·1회·5+1회와 중복 환급을 확인합니다.
기존 캐릭터 직접 API와 온보딩 획득도 함께 확인합니다. 운영 재화 차감 검증은
운영자가 승인한 테스트 계정·범위에서 수행합니다.
