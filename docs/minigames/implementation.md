# 미니게임 첫 구현

메인 방 오른쪽 리퀴드 아이콘에서 게임 목록을 엽니다. 첫 구현인 `루틴 러너`에 이어 사용자 요청으로 `고양이 계단`, `고양이 합치기`를 병렬 추가했습니다. 캐릭터는 기존 Rougether 고양이 원본을 사용하고 화면의 색상·폰트·리퀴드 버튼은 앱의 디자인 토큰을 따릅니다.

| 게임 | 코드 | 조작과 목표 |
| --- | --- | --- |
| 루틴 러너 | `room-runner` | 자동으로 달리며 화면 탭·Space·위 화살표로 장애물을 넘습니다. |
| 고양이 계단 | `cat-stairs` | 다음 계단에 맞는 좌우 버튼을 눌러 올라갑니다. 틀린 방향·시간 초과로 종료합니다. |
| 고양이 합치기 | `cat-merge` | 스와이프·방향키·화면 버튼으로 4×4 타일을 밀어 같은 숫자를 합칩니다. 막히거나 직접 마치면 기록을 저장합니다. |

## 구현 기본값

- 각 게임은 게임 코드와 규칙 버전 `1`로 구분합니다.
- 게임별 역대 최고 기록으로 전체 유저 순위를 제공합니다. 동점은 `1, 1, 3` 방식이며, 표시 순서는 해당 최고점을 먼저 달성한 사용자·사용자 ID 순입니다.
- 랭킹은 기록이 있는 활성 회원을 대상으로 하며 탈퇴 계정과 운영용 봇은 제외합니다. 사용자 닉네임은 현재 회원 정보를 조회하고 별도 사본을 저장하지 않습니다.
- 상위 50명과 내 기록·순위를 함께 반환합니다. 기록이 없으면 내 기록은 null입니다.
- 게임 보상과 입장 비용은 없습니다. 시즌이나 주간 리셋도 이번 구현에 포함하지 않습니다.
- 인증된 사용자에게 서버가 seed·만료 시각과 플레이 세션을 발급합니다. 점프 tick 또는 방향 입력을 같은 규칙으로 재현해 각 게임의 종료 조건과 점수를 확인합니다. 동일 제출 재시도는 중복 반영하지 않습니다.
- 클라이언트 자동 조작까지 판별하는 구조는 아닙니다. 서버 검증은 점수 임의 입력, 불가능한 점프, 조기 완료, 타인 세션과 중복 반영을 차단하는 범위입니다.

## 토스 게임 참고 자료

2026-09-12 조사에서 현재 앱 내 실시간 순위는 직접 확인되지 않았습니다. 다음은 시점이 명시된 성과입니다.

- 거지키우기: 토스 공식 2025-12-19 인터뷰에서 인기 게임 1위 사례. 탭 입력의 즉각적인 반응과 작은 성장 목표를 참고합니다. https://toss.im/apps-in-toss/blog/manababa
- 애니팡2: 위메이드플레이 2026-01-26 자료의 게임 전체 6위·퍼즐 3위. 후속 게임의 쉬운 규칙과 매치 퍼즐 구조를 참고합니다. https://corp.wemadeplay.com/press/2026/1/26/-2-top10-
- 용사단키우기: 토스 공식 2025-10-28 인터뷰의 70일 100만 유저 사례로, 순위 자체가 공개된 자료는 아닙니다. 같은 캐릭터 합치기 구조를 후속 후보로 둡니다. https://toss.im/apps-in-toss/blog/superjoy
- 무한의 계단: 토스 공식 포팅·로딩 최적화 사례. 단순 입력과 최고 기록 경쟁, 빠른 재시도 흐름을 참고합니다. https://toss.im/apps-in-toss/blog/apps-in-toss-game-optimization

추가 구현으로 계단 오르기와 2048 합치기를 선택했습니다. 위 게임의 실시간 순위 순서가 아니라 짧은 플레이와 서로 다른 조작 방식을 고려한 선택입니다. 아트·브랜딩은 Rougether에 맞게 자체 구현합니다.

## 작업 위치와 검증

- 서버: `../rougether-server-minigame`, `codex/minigame-runner`, origin/main 기준.
- 모바일: `../rougether-mobile-minigame`, `codex/minigame-runner`, origin/dev 기준.
- 모바일 작업 이슈: https://github.com/TripleS-soma/rougether-mobile/issues/1302
- 기존 더티 작업 폴더를 보존합니다. API와 기획 문서는 아직 spec에 없는 새 계약이므로 PR 게시 전 사용자 검토 대상입니다.
- 실제 로컬 서버·앱 연동에서 세 게임 모두 방 진입 → 게임 선택 → 플레이 → 점수 저장 → 해당 게임의 전체 랭킹 표시까지 확인했습니다. 최종 검증 점수는 계단 6점·합치기 80점·러너 31점이며 러너의 기존 최고 48점이 유지되는 것도 확인했습니다. 세 게임 모두 start 201 / finish 200 / leaderboard 200, 브라우저 실행 오류 0입니다.
- 추가 생성한 고양이 후보는 원본과 외형 차이가 있어 채택하지 않았습니다. 실제 게임의 cat-2/3 이미지는 기존 파일과 바이트가 동일합니다.
- 네이티브 실기기 검증, PR 게시, 배포는 수행하지 않았습니다. 정책 반영 초안은 이 폴더의 `privacy-update.md`와 `privacy-update.patch`이며 시행일·공지 근거는 출시 시점에 정해야 합니다.

## 최종 검증

- 러너 구현 시점 서버 전체 `./gradlew test`: 2,126개 통과, 7개 skip. 추가 2종 구현 후 미니게임 전체 패키지와 회원 탈퇴 통합 회귀 검사: 125개 전부 통과.
- 로컬 컨테이너 시작 지연을 처리하기 위해 user-api Test task에만 `TC_DAEMON=true`와 Hikari `connection-timeout=120000`을 적용한 임시 Gradle init script를 사용했습니다. 다른 모듈의 H2 설정은 유지했습니다.
- 모바일 전체 `npm test -- --maxWorkers=2 --forceExit`: 280개 suite·2,280개 테스트 통과. 기존에 문서화된 Jest 워커 종료 대기 경고가 남아 종료 옵션을 사용했습니다. AppShell 추가 집중 검사도 19개 통과했으나 종료 대기 원인은 확정하지 않았습니다.
- 모바일 전체 타입 검사 통과. lint 오류 없음(기존 app-shell 의존성 경고 1건), format·양쪽 `git diff --check` 통과.
- 고정 seed 리플레이 fixture를 Java와 JavaScript에서 교차 확인했습니다. 계단은 8개 fixture, 합치기는 6개 fixture로 종료·상한·난수·합치기 점수를 비교했습니다.
- 실제 화면과 결과 보고서는 모바일 `output/minigame-qa/`에 있습니다. `hub-three-games.png`, `cat-stairs-playing-live.png`, `cat-merge-playing-live.png`, `three-games-ui.json`이 최종 앱 연동 결과입니다. 테스트 데이터는 별도 로컬 DB의 가상 회원입니다.
- API·입력·종료 조건의 세부 계약은 [리플레이 계약](replay-contract.md)에 정리했습니다.
