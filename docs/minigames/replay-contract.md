# 미니게임 리플레이 계약

이 문서는 `room-runner`, `cat-stairs`, `cat-merge`의 현재 서버 구현을 설명합니다. 세 게임 모두 인증된 회원에게 서버 시드와 세션을 발급하고, 입력 기록을 재생하여 점수를 계산합니다. 클라이언트가 계산한 점수는 제출 계약에 포함하지 않습니다.

## 공통 API와 저장

- `GET /api/v1/minigames`: 게임 코드, 이름, 설명, `rulesVersion`을 반환합니다.
- `POST /api/v1/minigames/{gameCode}/runs`: `runId`, `gameCode`, `rulesVersion`, 양의 정수 `seed`, 게임별 `maxTicks`, `expiresAt`을 반환합니다. 세션은 발급 후 30분 동안 새 결과를 제출할 수 있습니다.
- `POST /api/v1/minigames/{gameCode}/runs/{runId}/finish`: 입력을 재생하여 `runId`, 이번 `score`, `bestScore`, `personalBest`, `rank`를 반환합니다.
- `GET /api/v1/minigames/{gameCode}/leaderboard`: 해당 게임의 누적 최고점 상위 50명, `myEntry`, `totalPlayers`를 반환합니다.

점수와 최고점은 기존 `game_code`로 구분합니다. 다른 게임의 세션으로 결과를 제출하면 404를 반환합니다. 랭킹은 미탈퇴 사람 회원만 포함하며, 동점은 공동 순위인 `1, 1, 3`으로 표시합니다. 동점 내부 순서는 최고점 달성 시각, 회원 ID 순입니다. 닉네임은 현재 회원 정보에서 읽고 사본을 저장하지 않습니다.

시작·종료·탈퇴는 같은 회원 행을 잠급니다. 이 잠금은 동시 최초 최고점 생성, 최고점 역행, 탈퇴 직후 게임 기록 재생성을 막습니다. 탈퇴 트랜잭션에서 모든 게임 세션과 최고점을 즉시 삭제합니다.

원본 점프·방향 입력은 DB에 저장하지 않습니다. 완료 후 입력의 SHA-256 digest, 서버 점수와 최초 완료 응답을 저장합니다. 같은 세션에 같은 입력을 재전송하면 만료 후에도 최초 응답을 반환하며, 다른 입력을 보내면 409를 반환합니다. 러너의 기존 digest 형식은 유지합니다.

## 시간과 입력 형식

`ticks`는 일시정지 시간을 제외한 60 Hz 게임 진행 시간입니다. 모든 게임에서 `1 <= ticks <= maxTicks`이고, 서버가 관측한 세션 경과 시간에 2초를 더한 값보다 큰 진행 시간은 거부합니다.

요청에는 `jumpTicks`와 `actions` 중 정확히 하나를 넣습니다. 각 배열의 tick은 오름차순이며 중복되지 않고, `1..ticks` 범위 안에 있어야 합니다. 방향은 대문자로 보냅니다.

러너 요청 예시:

```json
{"ticks":301,"jumpTicks":[180]}
```

계단·합치기 요청 예시:

```json
{"ticks":187,"actions":[{"tick":1,"direction":"LEFT"},{"tick":7,"direction":"LEFT"}]}
```

잘못된 입력 종류, 불가능한 상태 전이, 입력 개수 초과는 `MINIGAME_INVALID_REPLAY`로 거부합니다. 요청 DTO의 필수값·타입·기본 범위 위반은 공통 요청 검증 오류를 따릅니다.

## 루틴 러너: room-runner

규칙 버전은 1이며, 최대 18,000 tick과 600번의 점프를 허용합니다. 지상 점프, 장애물 생성·이동·충돌을 정수 물리로 재생합니다. 최초 충돌 tick 또는 18,000 tick 도달 시에만 완료할 수 있습니다. 점수는 `floor(ticks / 6)`입니다.

난수는 `state = (1664525 * state + 1013904223) mod 2^32`를 사용합니다. 장애물마다 너비·높이·다음 생성 간격에 차례로 난수를 소비합니다. 기존 러너의 난수 선택과 물리 규칙은 변경하지 않습니다.

## 고양이 계단: cat-stairs

규칙 버전은 1이며, 최대 7,200 tick과 1,200번의 좌우 입력을 허용합니다. 입력은 `LEFT`, `RIGHT`만 가능하며, 연속 입력 사이에 최소 6 tick이 필요합니다. UI는 이보다 빠른 입력을 무시하고 기록하지 않습니다.

초기 열은 0입니다. 다음 방향을 정할 때 러너와 같은 LCG를 한 번 소비하고, 상위 16비트의 마지막 비트로 좌우를 선택합니다. 현재 열이 -3 이하이면 오른쪽, 3 이상이면 왼쪽으로 강제하되 난수는 계속 소비합니다. 맞는 방향으로 이동한 뒤 다음 방향을 생성합니다.

초기 제한 시간은 180 tick입니다. 매 tick 시간을 먼저 1 줄이고, 0이면 입력 처리 전에 종료합니다. 따라서 만료 tick의 입력은 기록하지 않습니다. 방향을 맞히면 1점을 얻고 제한 시간을 `max(45, 180 - floor(score / 5) * 6)`으로 다시 설정합니다. 틀린 방향, 시간 만료 또는 7,200 tick 도달 시 완료합니다. 종료 후 tick이나 입력을 덧붙이면 거부합니다.

## 고양이 합치기: cat-merge

규칙 버전은 1이며, 최대 18,000 tick과 2,000번의 유효 이동을 허용합니다. `UP`, `RIGHT`, `DOWN`, `LEFT` 방향으로 4×4 보드를 이동합니다. 같은 타일 두 개를 합칠 때 생성된 타일 값만큼 점수를 얻으며, 한 이동에서 같은 타일을 반복 합치지 않습니다. 2,048을 만든 뒤에도 계속 플레이할 수 있습니다.

초기 타일 두 개와 이후 각 유효 이동의 새 타일은 같은 LCG로 생성합니다. 첫 난수의 상위 16비트를 빈칸 수로 나눈 나머지로 row-major 빈칸을 고릅니다. 두 번째 난수의 상위 16비트를 10으로 나눈 나머지가 0이면 4, 아니면 2를 생성합니다. LCG의 낮은 비트와 짝수 번 난수 소비 간 상관을 피하기 위해 두 선택 모두 상위 비트를 사용합니다.

보드가 달라지지 않는 이동은 UI에서 기록하지 않으며, 서버에 제출하면 거부합니다. 더 이동할 수 없는 보드에서 추가 입력을 보내도 거부합니다. 막힘, 2,000번 이동 또는 18,000 tick 도달 시 종료하며, 사용자가 중간에 기록 저장을 선택해도 됩니다. 유효 이동이 0번인 수동 종료는 `ticks >= 1`, `actions: []`로 제출합니다.

## 검증 자료

`user-api/src/test/resources/minigame/`에 모바일 엔진에서 만든 러너·계단·합치기 JSON fixture를 함께 보관합니다. Java verifier 테스트가 같은 seed와 입력을 재생하여 결과를 비교합니다. 서비스 통합 테스트는 게임 간 기록 격리, 최고점, 랭킹, 멱등 제출, 동시성, 롤백과 탈퇴 경합을 검증합니다.

이 검증은 임의 점수 제출과 규칙을 어긴 입력을 차단합니다. 규칙에 맞는 자동 플레이까지 사람의 플레이와 구분하는 인증 수단은 아닙니다. 게임에는 재화 보상을 연결하지 않습니다.
