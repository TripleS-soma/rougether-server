# 개인 AWS 전환 게이트웨이

`target.Caddyfile`은 서울의 고정 IP 인증서를 사용한다. 기본 모드인 `maintenance`는 503과 재시도 시간을 반환한다. `drain_furniture`는 신규 가구 요청을 막고 조회를 허용한다. `live_api`는 사용자 API, 앱 링크 검증, 초대·공동집 링크를 전달한다. 운영용 사용자 API와 연결할 때만 사용한다. 관리자 진입점은 별도로 관리한다.

`compat.Caddyfile`은 기존 주소를 사용하는 앱의 요청을 고정 IP로 전달한다. 배포할 때는 이전 원본 서버의 로컬 upstream 포트에만 연결한다. 기존 CloudFront가 사라지면 해당 주소를 쓰는 앱은 개인 AWS에 도달할 수 없으므로 앱 런타임별 업데이트 수신 경로를 확인한다.

11월 29일 Caddy 2.11.9에서 두 설정의 유효성을 확인했다. 로컬 호환 프록시를 통해 개인 AWS의 실제 TLS health를 조회했다. 격리 TLS 대상에서는 256 KiB POST를 한 번 처리하고 본문, 인증 헤더, 쿠키, Origin 및 쿼리가 보존되는지 확인했다. WebSocket 업그레이드 후 메시지를 왕복했고 링크 경로 네 종류에서 조회만 허용했다. 운영 CloudFront와 원본 연결 시험은 별도로 수행한다.
